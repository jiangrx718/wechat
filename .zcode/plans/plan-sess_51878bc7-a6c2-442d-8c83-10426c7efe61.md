# 基于 Eino 框架实现文件入库与搜索功能

## 技术选型（已确认）
- **向量数据库**：Milvus（`github.com/cloudwego/eino-ext/components/indexer/milvus` + `.../retriever/milvus`）
- **Embedding**：OpenAI（`github.com/cloudwego/eino-ext/components/embedding/openai`）
- **文件解析**：txt/markdown（标准库）、PDF（`pdfcpu`，项目已依赖）、docx（标准库 `archive/zip` + `encoding/xml`，无需新增依赖）

## 架构分层（严格遵循现有代码风格）

```
server/http/handlers/agent/      ← HTTP 层：接收文件上传、搜索请求
  ├─ impl.go                     NewAgentHandler / RegisterRoutes
  ├─ impl_document_ingest.go     POST /api/agent/documents/ingest   (multipart 单文件)
  └─ impl_search.go              POST /api/agent/search             (json query)

internal/service/agent/          ← 业务层：实现 Eino Indexer/Retriever 编排
  ├─ impl.go                     AgentService 构造、初始化 Milvus client + OpenAI embedder + indexer/retriever
  ├─ interface.go                AgentServiceIFace 接口（Ingest / Search）
  ├─ impl_document_ingest.go     解析文件→切片→indexer.Store
  ├─ impl_search.go              retriever.Retrieve→返回结果
  └─ loader/                     文件解析器
      ├─ loader.go               Load(filename, reader) 统一入口，按扩展名分发
      ├─ text.go                 txt/markdown
      ├─ pdf.go                  pdfcpu 提取文本
      └─ docx.go                 zip+xml 解析 docx
```

## 配置项（追加到 config/app.yml）
```yaml
agent:
  milvus:
    addr: "localhost:19530"
    username: ""
    password: ""
    collection: "wechat_doc_kb"
  embedding:
    api_key: "your-openai-key"
    model: "text-embedding-3-small"
    base_url: ""          # 可选，代理/兼容服务
    dimensions: 1536      # 与 model 对齐
  chunk:
    size: 500             # 每段字符数
    overlap: 50
  search:
    top_k: 5
    score_threshold: 0.3
```
（均可通过环境变量覆盖，复用 viper 的 `.`→`_` 替换）

## 关键实现细节

### 1. internal/service/agent/impl.go — 初始化
- `NewAgentService()`：读取 viper 配置，创建 Milvus client、OpenAI embedder。
- 构造 **Indexer**：自定义 `Fields` 使用 `FieldTypeFloatVector`（OpenAI 为 float 向量）+ `MetricType: COSINE`，dim = 配置的 dimensions，主键 `id`(VarChar)、文本 `text`(VarChar)、`vector`(FloatVector)。
- 构造 **Retriever**：`VectorField: "vector"`、`OutputFields: ["id","text"]`、TopK/ScoreThreshold 来自配置。
- 用包级 `sync.Once` 懒加载，避免每次请求重建。错误时通过 ServiceResult 返回（对齐 image_check 风格）。

### 2. loader — 文件解析（统一返回纯文本）
- `loader.Load(filename string, r io.Reader) (text string, err error)`
- txt/md：`io.ReadAll` 直接返回。
- pdf：`api.ExtractContentFile` 提取内容文本并拼接。
- docx：`archive/zip` 打开 → 读取 `word/document.xml` → 正则/xml 提取 `<w:t>` 文本。

### 3. impl_document_ingest.go — 入库
- `Ingest(ctx, filename, media []byte)`：
  1. `loader.Load` 得到全文。
  2. 按 `chunk.size/overlap` 滑窗切片（rune 安全，中文友好）。
  3. 每片构造 `*schema.Document{ID: uuid, Content: chunk, MetaData: {source: filename, index: i}}`。
  4. `indexer.Store(ctx, docs)` 返回 ids。
  5. 返回 `IngestResult{DocumentCount, ChunkCount}`。

### 4. impl_search.go — 搜索
- `Search(ctx, query string)`：
  1. `retriever.Retrieve(ctx, query)`。
  2. 遍历 docs，`doc.Score()` 取相似度。
  3. 返回 `[]SearchItem{Content, Score, Source}`。

### 5. handler 层（对齐 miniwechat 风格）
- `impl_document_ingest.go`：`ctx.FormFile("file")` → 限制大小 → 读字节 → `service.Ingest`。
- `impl_search.go`：`ctx.Bind(&SearchReq{Query, TopK})` → `service.Search`。
- 统一用 `response.Successful / ParameterError / InternalError / Failed` + `utils.SugarContext` 日志。
- 在 `server/http/handlers/handler.go` 的 `RegisterRoutes` 中追加注册。

### 6. service interface（对齐 interface.go 风格）
```go
type AgentServiceIFace interface {
    Ingest(ctx context.Context, filename string, media []byte) (common.ServiceResult, error)
    Search(ctx context.Context, query string, topK int) (common.ServiceResult, error)
}
type IngestResult struct {
    DocumentCount int `json:"document_count"`
    ChunkCount    int `json:"chunk_count"`
}
type SearchItem struct {
    Content string  `json:"content"`
    Score   float64 `json:"score"`
    Source  string  `json:"source"`
}
```

## 说明与权衡
- Milvus client 连接失败时服务**不 panic**，仅在调用 agent 接口时返回 500（其余业务不受影响）——惰性初始化。
- OpenAI embedding 维度需与 collection 的 vector dim 严格一致，配置中显式声明，首次入库时创建集合。
- 为保持简洁，文本切片用基于 rune 的定长滑窗（不引入额外 splitter 依赖）；如后续需要更智能切分可换 `eino` 的 transformer/splitter。
